# DNN Platform Language Pack for Turkish (tr-TR)

Turkish (Türkiye) language pack for [DNN Platform](https://github.com/dnnsoftware/Dnn.Platform).

Versions available:
* DNN Platform 10.04.00

## Installation

Download the latest `Dnn_Platform_Language-Pack-TR-TR_<version>.zip` from the
[Releases](../../releases) page and install it in DNN Platform under
**Persona Bar > Settings > Extensions > Install Extension**.

## How to contribute

**Important:** Before you start translating, please read the [Turkish translation style guide](.github/COMMON_TERMS.md)
(in Turkish). It defines the form of address (*siz*) and the standard terms used throughout the pack.

All you need is a GitHub account. All contributions are made as pull requests to the **develop** branch.

### Quick edits (in the browser)

1. Fork this repository to your own account.
2. Edit the `.tr-TR.resx` file you want to correct directly on GitHub.
3. Open a pull request to the **develop** branch.

### With a working DNN Platform site

1. Fork the repository and clone it to your computer.
2. Translate or correct strings in DNN Platform (**Settings > Site Settings > Languages**).
3. Copy the files from the site into the repository and update the manifest:

   ```powershell
   .\tools\Sync-FromSite.ps1 -SitePath C:\path\to\dnn-platform-site
   .\tools\Build-Manifest.ps1
   ```

4. Commit your changes and open a pull request to the **develop** branch.

`Build-Manifest.ps1` regenerates the `Resources\DNNCE_tr-TR.dnn` manifest from the files in the repository.
`Build-Manifest.ps1 -Check` runs automatically on every pull request and fails on invalid XML or an out-of-date manifest.

> Some file paths can exceed 260 characters on Windows. If cloning fails, run: `git config --global core.longpaths true`

## Repository layout

Path | Purpose
--- | ---
`Resources/` | Contents of the install package, mirroring the DNN Platform site folder structure
`Resources/DNNCE_tr-TR.dnn` | Package manifest, generated by `tools/Build-Manifest.ps1`; do not edit by hand
`Resources/ReleaseNotes.txt` | Release notes shown during installation
`tools/Sync-FromSite.ps1` | Copies `*.tr-TR.resx` files from a working DNN Platform site into `Resources/`
`tools/Build-Manifest.ps1` | Generates the manifest; `-Check` validates it (used by CI)

New resource files for extensions not listed in the `$PackageMap` of `tools/Build-Manifest.ps1` go into the core pack.
Add a mapping there when a new DNN Platform extension ships its own resources.

## New version release

When the language pack is ready for a new version:

* Create a branch called `release/x.x.x` where x.x.x is the version of the release (DNN Platform version).
* Wait a few minutes and you should see a new commit on that branch that updates the manifest automatically with the version taken from that branch.
* When that commit is in, create a pull request from `release/x.x.x` that targets `master`. Merging it packages the language pack and creates a **draft** GitHub release; review and publish it.
* Optionally create another pull request from `release/x.x.x` targeting `develop` so `develop` has the latest version number too.
* Add an entry to `Resources/ReleaseNotes.txt` and to the version list above.
